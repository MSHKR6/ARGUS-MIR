# ARGUS

**Поведенческий контроль безопасности сайта на стороне клиента.**

Argus видит, что скрипты делают в браузере посетителя: какие загрузились, какие поля формы читают
и куда отправляют данные. Он запоминает нормальное поведение сайта (эталон) и сообщает о любом
отклонении — одновременно как о **вторжении** и как о **нарушении 152-ФЗ**.

> Дипломный проект (ВКР), ДГТУ, кафедра «Информационная безопасность в вычислительных системах и сетях».
> Тема: «Метод поведенческого контроля безопасности веб-ресурсов на стороне клиента для обнаружения
> вторжений и нарушений режима обработки персональных данных». Автор — М.А. Карый (mshkr6).

## Зачем

WAF и антибот защищают вход на сайт, но не видят, что происходит внутри страницы. Два класса угроз
остаются без покрытия:

1. **Вторжение на клиенте** — скиммеры (Magecart), подмена плагина или CDN, внедрённые редиректы и iframe.
2. **Утечка ПДн за рубеж** — с 1 июля 2025 г. первичный сбор персональных данных допускается только в РФ;
   иностранный счётчик, получающий e-mail из формы, — это штраф до 6 млн ₽.

## Как работает

```
браузер посетителя                        сервер Argus
┌──────────────────────┐   батчи POST    ┌──────────────────────────────────────────┐
│ sensor.js            │ ──/collect────▶ │ обучение:   событие → эталон              │
│  скрипты + SHA-256   │                 │ наблюдение: событие → детектор → риск rᵢ  │
│  сеть + инициатор    │                 │   → вторжение | 152-ФЗ → риск посещения R │
│  чтение полей (тип)  │                 │   → изменение «было/стало» → Telegram     │
└──────────────────────┘                 └──────────────────────────────────────────┘
```

| Шаг | Что происходит |
|---|---|
| 1. Датчик | Одна строка `<script>` в `<head>`. Пишет события: загрузка скрипта (с хешем), сетевые запросы, чтение полей формы — **только категория** («телефон», «карта»), не значение. |
| 2. Эталон | В режиме обучения сервер строит профиль нормы: скрипты и их хеши, получатели, кто какие поля читает, потоки `категория ПДн → скрипт → получатель`. |
| 3. Наблюдение | Каждое отклонение получает вес `rᵢ`; риск посещения `R = 1 − ∏(1 − rᵢ)`. Порог тревоги — **0,6**. |
| 4. Решение | Тревога в Telegram. Владелец в кабинете: «Это мы — принять в эталон», «Это атака — инцидент» или «Скрыть». |

Эксперимент на стенде: **9 из 9 атак** обнаружено, **0 ложных тревог**, 36–62 мс до находки в большинстве сценариев.

## Что в репозитории

```
site/
├── index.html        сайт «сто глаз»: купол глаз, миф, демо-стенд с атаками, эксперимент,
│                     кабинет, данные; в шапке — «Личный кабинет» с окном входа
├── cabinet.html      прототип личного кабинета (демо-данные): у каждого сайта свой глаз
└── assets/argus.css  общие стили: токены ливреи, кнопки, окно входа, статусы
docs/
└── kabinet.md        устройство личного кабинета и вопрос об эталоне клиента
```

Датчик, сервер, детектор и стенд пока живут в локальной папке `dozor-mvp` и будут перенесены сюда отдельно.

## Как открыть

Сборка не нужна — это статические страницы. Откройте `site/index.html` в браузере или поднимите локальный сервер:

```bash
python3 -m http.server 8080 --directory site
```

Затем откройте <http://localhost:8080>. Кнопка «Личный кабинет» открывает окно входа; в прототипе любой вход
ведёт в демо-кабинет, данные никуда не отправляются.

## Дизайн

Мотив — сто глаз Аргуса. Ливрея болида: карбон, серебро-лаванда, фиолетовый. **Красный — только угроза**, 152-ФЗ — фиолетовый.
Шрифты: Onest (текст), Unbounded (логотип), JetBrains Mono (код). Одна тёмная тема.

**Почему Argus.** Аргус Паноптес — стоглазый страж из греческих мифов: часть глаз всегда открыта, даже когда он спит.
Обмануть его смог лишь Гермес — поэтому Argus не верит скриптам на слово, а сравнивает поведение с эталоном.
